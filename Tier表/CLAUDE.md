# CLAUDE.md — Tier表（投稿パターン2）

## これは何

ジャンル内の対象（資格・商品・選択肢など）をS〜Dのようなランクに並べるインフォグラフィック。フォロー・拡散を狙う型（→ ルートCLAUDE.mdの役割分担）。

**HTML/CSSで直接Tier表本体を生成する。** 構成案だけ渡すのではなく、`ノート画像生成/`と同じ仕組み（HTML→PNG）で画像そのものをClaudeが作る。

## 納品形式はテーマで分かれる

Tier表のテーマによって、必要な素材が変わる。

- **画像素材が必須なテーマ**（例: 商品の表紙・パッケージなど、見た目そのものが判断材料になるもの）：対象の画像を集めて渡す必要がある。**この画像収集は著作権に注意すること**。他者が撮影・制作した画像（商品パッケージ写真、書影など）を商用配布物に含めてよいかは必ず確認する。正規の画像を想定し、海賊版・転載NG画像は避ける
- **画像素材が不要なテーマ**（属性・難易度・特徴の比較など、テキストとレイアウトだけで表現できるもの）：Claudeが**HTML→PNGで画像まで生成できる**。こちらのほうが著作権リスクがなく、量産しやすい

新しいジャンルで始めるときは、まず「画像素材なしで作れるテーマ」を優先すると立ち上げが早い。

## デザイン構造

質感をCSSで一から描こうとせず、「フリー素材の背景写真/質感＋縁取りタイトル文字＋色分けされたTierプレート＋白バッジの表」をレイヤーとして重ねて作る。HTMLは「レイヤーを重ねる合成台」として使う。

- 大題は極太ディスプレイ体
- Tierごとに明暗差・色差のあるプレートに項目を載せる（地に直置きしない）
- 長い注記・注釈・凡例は入れない（→ ルートCLAUDE.md「小さい文字の補足を置かない」）
- `* { line-break:strict; word-break:normal; }`を自分で書き、2行以上になる文は`<br>`で意味の切れ目で折る（`generate_note.py`を通らないので共通CSSの保険が効かない）

## 運用フロー

1. ユーザーが「今日のTier表作って」、またはテーマを指定して依頼
2. テーマを選ぶ（指定がなければClaudeが提案。過去ネタとの重複を避ける）
3. Tier構成案を作る（Tierごとの対象＋一言キャッチコピー）。web検索で情報を補ってよい
4. 画像素材が必要なテーマなら、対象の画像を収集して`draft/<日付>_<案名>/`にまとめる（著作権に注意。上記参照）
5. HTMLでTier表本体を組み、`render.js`でPNG化する（画像不要なテーマの場合）
6. `draft/`に構成案・画像・生成HTML/PNGを納品。最終的なレイアウト調整はユーザーがCanva/CapCutで行う場合もある

## 作業フォルダ規約

- `inbox/` … 未整理の素材置き場。文字起こし・メモ・URL一覧・思いつきなどを入れる
- `reference/` … Claudeに参照させたい情報（読者ペルソナ・過去記事・ブランドルール・参考リンクなど）
- `draft/` … 下書き・構成案・途中の出力。完成物と混ぜない
- `output/` … 完成物のみ
- `archive/` … 使い終わったファイルの移動先（削除ではなく移動で管理）

## 素材調達の役割分担

- **背景・キャラ素材（汎用・使い回し可能なもの）**：ユーザーが自分で用意して`reference/`に置く。Claudeはこれを探しに行かない
- **項目ごとの画像（テーマ固有のもの、必要な場合のみ）**：Claudeがテーマごとにweb検索して収集する。正規の画像を想定し、海賊版・転載NG画像は避ける

## サンプル

`draft/部活の忙しさTier表_見本/`に、画像素材なしでHTML→PNGだけで完結する構成例を1本同梱している。テキストとレイアウトだけでTier表が作れることの参考にする。
